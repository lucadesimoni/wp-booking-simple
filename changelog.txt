*** WP Booking Simple Changelog ***

2026.09.26 - version 1.24.0
 * Security - The SMTP password is stored encrypted (AES-256-GCM, key derived from the wp-config.php salts) instead of in plain text. A password saved by an earlier version keeps working and is encrypted the next time the settings are saved. Hosts without OpenSSL keep the previous behaviour. Changing the salts means entering the password again.
 * Tweak - WordPress.org directory preparation: the "Send test email" button's inline <script> moved into assets/js/admin.js; date() replaced by gmdate() (identical under WordPress); translations load on init instead of plugins_loaded (WordPress 6.7 warns about earlier loading).
 * Tweak - Generic settings placeholders (no bank, chalet or family names); plugin header gains License / License URI and points Plugin URI at the project repository.
 * Tweak - Readme: External services section (the plugin contacts no external service).

2026.09.25 - version 1.23.0
 * Compatibility - Requires WordPress 6.5 or later (was 5.0); tested up to 7.1. The block editor controls use the WordPress 7.0 control styles, so 6.7-6.9 no longer log deprecation warnings.
 * New - "Theme colors" scheme under Settings > Booking Form > Colors. The form, calendar and buttons then follow the active theme: the Astra global palette plus Astra's Customizer button colors, corner radius and heading font; otherwise Elementor's global colors and fonts, or a block theme's palette. The default stays the plugin's dark red, so existing sites look exactly as before. The stylesheet is now driven by --wpbs-* custom properties (filter: wpbsl_theme_scheme_vars).
 * Fix - Block color pickers ignored the Astra palette. Astra (and block themes) hand out colors as CSS variables such as var(--ast-global-color-0), which the color validator rejected, so picking a palette color silently did nothing. Palette variables are now accepted and keep following later palette changes.
 * Fix - A per-block accent color leaked into every form on the page: only the first selector of the focus rule (input) was scoped to the block, so the select/textarea focus color applied site-wide. Every selector is now scoped.
 * New - Gutenberg / Spectra: both blocks use block API v3 (the iframed editor) and support wide/full alignment, an HTML anchor, margin and padding. The booking form shows a live preview in the editor, and the booking styles load inside the editor canvas.
 * Fix - Content saved with the pre-rename block names (wp-booking-system/*) showed as an unsupported block in the editor; those names are now registered in the editor too (still hidden from the inserter).
 * New - Elementor: title color and typography on both widgets; button typography, form background, padding and shadow on the form widget. Widgets declare their style/script dependencies, so they also work in Elementor popups and templates.
 * Fix - Elementor editor: after changing a widget setting, the re-rendered calendar stayed empty and the date picker, price calculation and submit did nothing. The front-end script now initialises idempotently, hooks Elementor's element_ready, and uses delegated event handlers (window.wpbsInit() re-runs it).
 * Tweak - German (de_DE, de_CH) translations for every new string.

2026.08.11 - version 1.22.1
 * Fix - The German translation is complete again. 33 strings had no translation at all (the Elementor widget labels, the block descriptions, the new form-field settings, "Select a date", the IBAN hint and more), because the template was maintained by hand while nothing checked that the catalogs kept up. tools/i18n/build-catalogs.py now regenerates the .pot and both .po files from the source and fails when any string is left untranslated.
 * Fix - Saving the settings no longer freezes the email templates in whatever language the admin was viewing. The form pre-fills each field with the rendered default, so opening the Email Templates tab and pressing Save used to store the English text permanently - after which the emails stayed English on a German site. An unedited field is now stored blank and keeps following the site language.
 * Fix - The guest count on the guest's manage page said "1 Kinder"; it built its own unpluralised string instead of the one the emails use. Both now share WP_Booking_Simple_Helpers::guests_label().
 * Fix - The payment reference in the QR bill and the confirmation email is translatable, so it reads "Buchung Nr. 12 ..." on a German site instead of "Booking #12 ...".
 * Fix - The IBAN hint under Settings showed mojibake ("CHâ¦" instead of "CH…") from a double-encoded ellipsis in the source, present since 1.18.0.
 * Fix - The Elementor widget labels were invisible to the string extractor, so includes/elementor/ was never translated.
 * Improvement - The Swiss German (de_CH) catalog no longer contains "ß"; it is generated from de_DE with Swiss spelling.

2026.08.11 - version 1.22.0
 * New - Remove fields from the booking form: last name, phone and the number of kids can each be switched off under Settings > Booking Form, alongside the existing notes, owner and visitors toggles. Check-in, check-out, adults, first name and email stay mandatory - a booking cannot be priced, held or confirmed by email without them.
 * New - A hidden field is enforced nowhere: the form and the AJAX handler read one shared field map, so switching a field off also stops it being required, discards anything a hand-crafted request sends for it, and keeps the quoted price equal to the booked price. Requiring a phone number now only applies while the phone field is shown.
 * Fix - Guest counts in emails read "2 adults, 1 kid" instead of "1 kids", and kids are left out entirely when there are none, so a site with the kids field switched off no longer sends ", 0 kids".

2026.08.11 - version 1.21.0
 * Rename - The plugin is now "WP Booking Simple" throughout: plugin name, folder and ZIP slug (wp-booking-simple), main file, text domain, classes, constants, functions, script/style handles, admin page slugs and the Elementor/Gutenberg category. Existing shortcodes ([wp_booking_form_luca], [wp_booking_manage_luca], [wp_booking_calendar_luca]) and blocks (wp-booking-system/calendar, wp-booking-system/form) stay registered as hidden aliases, so pages that already embed them keep rendering unchanged.
 * Compatibility - Option names and the booking/history database tables are deliberately unchanged, so updating an existing site keeps every booking, setting and auto-created page.
 * Fix - Removed a leftover second plugin header file that WordPress listed as a separate plugin and that fataled on activation because the files it loaded no longer exist.
 * Fix - The bundled front-end libraries (flatpickr, FullCalendar, QR generator) are now committed and shipped; an unanchored .gitignore rule had excluded them, so the date picker, availability calendar and TWINT QR code silently did nothing in every install.
 * Fix - dbDelta could never diff the schema because the CREATE TABLE statement used IF NOT EXISTS, which made it read the table name as "IF"; schema upgrades now apply.
 * Fix - Declared Requires PHP: 7.2 so WordPress blocks activation on unsupported PHP instead of fataling.
 * Improvement - build.sh now fails when a runtime asset is missing instead of quietly publishing an incomplete ZIP, and tools/fetch-vendor.sh restores the bundled libraries reproducibly.

2026.06.16 - version 1.19.0

The same panel appears on the manage page, and a new {payment_info} merge tag adds it to the confirmation email (included in the default template).

2026.06.16 - version 1.18.1
 * New - "Refunded" payment status, completing the payment lifecycle: mark a booking refunded from the editor (set the amount paid back to 0); it shows a Refunded badge on the bookings list, is recorded in the change history, and the TWINT QR code never shows for a refunded or cancelled booking.
 * Tweak - Verified end to end: the guest's TWINT QR tracks the outstanding balance (e.g. 500 → 300 after a deposit) and disappears once the booking is paid in full, cancelled or refunded.

2026.06.16 - version 1.18.0
 * New - TWINT / Swiss QR-bill payment integration (free, no merchant account). When enabled, a booking with an outstanding balance shows a Swiss QR code on the guest's manage page; the guest scans it with TWINT or any Swiss banking app to pay. Configure your IBAN and address under Settings > General > TWINT / QR-bill Payments. The payload follows Swiss Payment Standards QR-bill 2.0 and the QR generator (MIT, Kazuhiko Arase) is bundled with the plugin — nothing is sent to an external service.
